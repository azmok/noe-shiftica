前回までのシリーズで、「AI社員」の正体はAIに役割を与えたものでしかない、と書きました。

今回からは、実際に作ってみます。Webサイトを作るAIチームを、ゼロから組み上げていきます。

最初に、いちばん大事なことを書いておきます。

プログラミングの知識は、まったく必要ありません。
コードを書くのも、ファイルを作るのも、全部AIがやります。
あなたがやるのは、この記事にある文章を貼り付けることだけです。

「そんなうまい話が」と思うかもしれませんが、2026年の今はこれが普通です。むしろこの事実こそが、高額な講座が不要な理由でもあります。

この記事で作るもの

2人のAIが、役割を分けて働くチームです。

あなた「海の見えるカフェのページを作って」
      ↓
デザイナー役のAI ── どんなページにするか考える
      ↓ 考えた内容を渡す
コーダー役のAI  ── 実際のWebページを作る
      ↓
Webページが完成する

テーマを1つ伝えるだけで、勝手に構成が考えられ、勝手にページが出来上がります。かかる時間は15分ほどです。

先に、お金の話をします

気持ちよく進めるために、費用の話を最初に済ませておきます。

結論から言うと、月3,000円ほどのサブスクを1つ契約している状態が、いちばん快適です。

サービスプラン月額の目安
Antigravity（Google）Google AI Pro約3,000円
Claude Code（Anthropic）Claude Pro約3,000円
Codex CLI（OpenAI）ChatGPT Plus約3,000円

どれか1つで大丈夫です。 すでにChatGPTやClaudeを契約している方は、追加の費用はかかりません。 そのまま使えます。

なぜサブスクを勧めるのか

正直に書きます。無料でも試すことはできますが、使える回数がかなり限られています。 途中で上限に達して、数日待たされることもあります。

せっかく作り始めたのに止まってしまうと、それだけで嫌になります。最初の一歩でつまずかないために、月3,000円は妥当な投資だと僕は考えています。

それに、有料プランでは最新の高性能なモデルが使えます。同じ手順でも、出来上がるものの質が変わります。

数十万円の講座と比べてみてください

一方こちらは月3,000円。しかも月単位なので、合わなければすぐやめられます。桁が2つ違います。

数十万円を払う前に、まず月3,000円を1か月だけ試してみる。
そのほうが確実で、速くて、失うものが少ない——これが僕の考えです。

用意するもの（2つ）

① 作業する場所

AIが実際にファイルを作る場所です。契約しているサービスに合わせて選んでください。

▸ Googleを使う場合：Antigravity IDE

antigravity.google を開いてください。Windows・Mac・Linuxすべてに対応しています。

⚠️ ここで注意が必要です。 ダウンロードページには、似た名前のものが4つ並んでいます。

名前何のためのものか
Antigravity IDE← 今回使うのはこれです
Antigravity 2.0複数の作業をまとめて管理するアプリ
Antigravity CLI黒い画面（ターミナル）から使う版
Antigravity SDK開発者が自分でAIを組む用の部品

「Antigravity IDE」を選んでください。 理由は、1つの画面の中に「ファイルの一覧」「AIと会話する欄」「文章を書き換える機能」がすべて揃っているからです。あとの手順が、この1画面だけで完結します。

インストールしたら起動して、Googleアカウントでログインしてください。

▸ Claudeを使う場合：Claude Code

Macの方は、ターミナルで次を実行します。

brew install --cask claude-code

Windowsの方や、うまくいかない場合は公式のインストール手順をご覧ください。作業したいフォルダで claude と入力すると起動し、初回はブラウザでログインを求められます。

▸ ChatGPTを使う場合：Codex CLI

# Mac / Linux
curl -fsSL https://chatgpt.com/codex/install.sh | sh

# Windows（PowerShell）
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"

インストール後、codex と入力すると起動します。「Sign in with ChatGPT」を選べば、契約中のプランでそのまま使えます。

📌 どれを選んでも、この先の手順はまったく同じです。 貼り付ける文章も共通です。

② AIを呼び出す鍵（Gemini APIキー）

「APIキー」は、作ったプログラムがAIを呼び出すための鍵です。

ここで混乱しやすいので、はっきり分けておきます。

作業する場所（Antigravity IDE など）
  → AIがあなたの代わりにファイルを作る
  → 契約しているサブスクで動く

APIキー
  → 出来上がったプログラムがAIを呼ぶ
  → サブスクとは別の仕組み。別途取得が必要

サブスクを契約していても、APIキーは別に取得する必要があります。 ここは多くの人がつまずく点なので、覚えておいてください。

取得は1分で終わります。

① https://aistudio.google.com/apikey を開く
        ↓
② Googleアカウントでログイン
        ↓
③ 「APIキーを作成」をクリック
        ↓
④ 表示された文字列をコピーする
   （AIza... で始まる長い文字列です）

💰 料金について：この記事で作るものは、1回動かしてもごくわずかな金額です。ただし利用量に応じた課金があるので、正確な単価は公式の料金ページで確認してください。

コピーした鍵は、あとで使います。メモ帳などに一時的に貼っておいてください。

作ってもらう（3ステップ）

STEP 1
作ってもらう

用意したツール（Antigravity IDE、Claude Code、Codex CLIのいずれか）を開いて、AIと会話する欄に、次の文章をそのまま貼り付けてください。

Pythonで「役割を持つAIエージェント」の最小構成を作ってください。
私はプログラミング初心者なので、必要なものはすべて自動で用意してください。

## 環境
- 作業フォルダは ai-team という名前で新規作成する
- パッケージ管理には uv を使う（未インストールなら導入から行う）
- 必要なパッケージは google-genai と python-dotenv

## 作ってほしいファイル

### .env
GEMINI_API_KEY=ここにキーを貼ってください
（この1行だけ。実際のキーは私があとで貼ります）

### .gitignore
.env と output/ と .venv/ を除外する

### agents.py
- .env からAPIキーを読み込む
- agent(role, task, model="gemini-2.5-flash") という関数を1つ定義する
- role は system_instruction として渡す
- task は contents として渡す
- 戻り値は応答テキストのみ

### roles.py
DESIGNER と CODER という2つの文字列を定義する
- DESIGNER: UIデザイナー。渡されたテーマから、1枚のWebページの
  構成・配色・フォント・各セクションの文言を決める。
  仕様だけを日本語で書き、コードは書かない
- CODER: フロントエンドエンジニア。渡された仕様を、
  外部ファイルに依存しない1枚のHTMLとして実装する。
  レスポンシブ対応。出力はHTMLコードのみ

### main.py
- THEME という変数にテーマを書く
  （初期値は「海の見える個人経営のカフェ。落ち着いた大人向けの雰囲気」）
- デザイナーを呼んで仕様を作り、output/design.md に保存
- その仕様をコーダーに渡してHTMLを作り、output/index.html に保存
- AIの返答からコードフェンスを取り除く処理を入れる
- 各工程の進行状況を日本語でわかりやすく表示する

### README.md
セットアップ手順と実行方法を書く

## 最後に
- 作ったファイルの一覧と、それぞれの役割を日本語で説明してください
- 私が次に何をすればいいかも教えてください

貼り付けたら、あとは待つだけです。フォルダの作成から、必要な道具の準備、コードの作成まで、全部やってくれます。

終わると、AIが「次はこうしてください」と教えてくれます。

STEP 2
鍵を1行貼る

ここだけが、あなたの手作業です。

AIが .env というファイルを作ってくれています。画面の左側にあるファイル一覧から、それをクリックして開いてください。

中身はこうなっています。

GEMINI_API_KEY=ここにキーを貼ってください

この「ここにキーを貼ってください」の部分を消して、さきほどコピーした鍵に置き換えます。

GEMINI_API_KEY=AIzaSy...（あなたの鍵）

保存したら完了です。

💡 なぜAIに鍵を渡さないのか：AIとの会話に鍵を書くと、その内容が記録として残る可能性があります。鍵は、あなたのパソコンの中だけに置いておくのが安全です。この1回の手作業は、そのためのものです。

⚠️ .env の中身は、誰にも見せないでください。鍵が漏れると、他人にあなたの分の料金を使われてしまいます。

また会話欄に戻って、こう伝えてください。

これだけです。 コマンドを打つ必要もありません。

こんな表示が流れれば成功です。

できあがった output/index.html を開いてみてください。1枚のWebページができています。

💡 もっと質を上げたい場合は、こう伝えてください。有料プランなら、より高性能なモデルが使えます。

何が起きたのか——コードを読んでみる

ここからは、読むだけのパートです。何かを書く必要はありません。

AIが作ってくれたファイルの中身を見ると、「AI社員」と呼ばれているものの正体がはっきりします。ここが、この記事でいちばん価値のある部分です。

別々の机で働く、という発想

まず、いちばん大事な考え方から説明します。

AIには「一度に見渡せる情報の量」に限りがあります。作業机の広さをイメージしてください。

会話を続けると、それまでのやり取りが全部この机の上に積み上がっていきます。そして机が散らかると、AIの精度そのものが落ちます。

AIは机の上の情報のうち、最初と最後にはよく反応するのに、真ん中に埋もれたものを見落としやすいという性質があります。長い会議の冒頭と結論だけ覚えていて、中盤を忘れてしまう感覚に近いものです。

ここで、多くの人がやってしまう方法があります。

1人のAIに
「今はデザイナーとして考えて」
「次はコーダーとして書いて」
と指示を切り替える

これは役割分担ではありません。 同じ1つの机の上で、AIが服を着替えているだけです。デザイナーとして考えた内容も、コーダーとして書いた内容も、全部同じ机に積み上がっていきます。

本当の役割分担は、こうです。

デザイナー役 ── 専用の机で作業する
                （他の作業は机の上にない）

コーダー役   ── 別の専用の机で作業する
                （届くのは完成した仕様だけ）

机そのものを分ける。 これが「役割を持たせる」ということの正体です。

では、AIが作ったコードのどこで机を分けているのか。ここが面白いところです。

「AI社員」の本体は15行

agents.py というファイルを開いてみてください。だいたいこんな内容になっているはずです。

import os
from dotenv import load_dotenv
from google import genai
from google.genai import types

load_dotenv()
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])


def agent(role, task, model="gemini-2.5-flash"):
    """役割と仕事を渡すと、結果が返ってくる"""
    res = client.models.generate_content(
        model=model,
        config=types.GenerateContentConfig(system_instruction=role),
        contents=task,
    )
    return res.text

読めなくても大丈夫です。注目してほしいのは1か所だけです。

system_instruction=role

この system_instruction というのが、「あなたは誰として振る舞ってください」という指定です。

ここに「あなたはデザイナーです」という文章を渡せばデザイナーになり、「あなたはコーダーです」と渡せばコーダーになります。

これだけです。 数十万円の講座で教えられている「AI社員」の中核は、この15行に収まっています。

役割の正体は、ただの文章

次に roles.py を開いてみてください。

DESIGNER = """あなたはUIデザイナーです。
渡されたテーマから、1枚のWebページの仕様を決めてください。

- ページ全体の構成（どのセクションを、どの順番で置くか）
- 配色（背景・文字・アクセントの3色を、カラーコードで指定）
- 各セクションに入れる文言の内容

コードは書かないでください。仕様だけを日本語で書いてください。"""


CODER = """あなたはフロントエンドエンジニアです。
渡された仕様を、1枚のHTMLファイルとして実装してください。

- スマホでも崩れないようにする
- 仕様にないものは追加しない
- 出力はHTMLコードのみ。説明文は不要"""

見てのとおり、ただの日本語の文章です。 プログラムらしいものは何もありません。

つまり——「AI社員を作る」というのは、こういう文章を書くことでした。

そして、ここを書き換えれば、そのまま別の社員になります。「あなたは経理担当です」と書けば経理係に、「あなたは校正者です」と書けば校正係になります。特別な技術は必要ありません。

💡 うまく書くコツが3つあります。

  1. やってほしくないことを書く——「コードは書かない」「仕様にないものは追加しない」のような線引きが、暴走を防ぎます
  2. 出し方を指定する——「日本語で」「HTMLだけ」と書かないと、余計な前置きが混ざります
  3. 具体的に書く——「配色」ではなく「3色をカラーコードで」と書くほうが、精度が上がります

なぜ机が分かれるのか

最後に main.py の、いちばん大事な2行を見てください。

design = agent(DESIGNER, "このテーマで仕様を作って")
result = agent(CODER,    "この仕様を実装して" + design)

ここで机を分ける処理は、どこにも書かれていません。

実は——書く必要がないんです。

AIを呼び出す仕組みは、前回のやり取りを覚えていません。 呼び出すたびに、そのとき渡された内容だけを見て応答します。

つまり呼び出すたびに、机が自動的にまっさらな状態から始まります。

デザイナーが迷った過程も、書きかけて消した案も、コーダーの机には乗りません。届くのは、完成した仕様だけです。

これが、たった15行で役割分担が成立する理由です。特別な仕組みが分けているのではなく、最初から分かれているんです。

裏を返すと、大事な注意点があります。

必要な情報は、毎回きちんと渡す必要があります。
「さっきの仕様で」は通じません。

だからコードでは、デザイナーの結果を + design という形で、コーダーへの指示にくっつけて渡しています。この一手間が、机が分かれていることの証拠でもあります。

うまくいかないときは

基本的には、エラーの文章をそのままAIに貼って「直してください」と伝えれば解決します。 それが今のやり方です。

よくあるものだけ、先に挙げておきます。

症状どうするか
「APIキーが見つかりません」と出る.env に鍵が貼られているか確認してください。「ここにキーを貼ってください」の文字が残っていないかも確認を
「モデルが見つかりません」と出るAIに「モデル名が古いようです。最新のものに直してください」と伝えてください
「上限に達しました」と出る短い時間に呼びすぎています。1分ほど待ってから、もう一度実行してもらってください
ページに変な記号が表示されるAIに「HTMLに余計な記号が混ざっています。取り除く処理を確認してください」と伝えてください
できたページが英語になっているroles.py に「日本語で書いてください」を追加するよう、AIに頼んでください
