前回までの2本で、Obsidianの`[[リンク]]`が手作業の関係記録であること、そして数年書き溜めると4つの壁が現れることを見てきました。

では、その壁を越える技術はどうなっているのか。今回は、その土台となる4つの言葉を順番に積み上げて解説します。専門用語は一切前提にしません。

読み終える頃には、次回扱う「2026年の最適解」がそのまま理解できる状態になっています。

## Vector（ベクター）——意味を座標に変換する

文章を、地図の上の1点だと考えてください。

「犬」という文章と「猫」という文章は、地図上でとても近い場所に置かれます。どちらも身近な動物の話だからです。一方「確定申告」という文章は、まったく離れた場所に置かれます。話の内容が違うからです。

**Vector**とは、この「地図上の座標」そのものです（専門用語では**embedding**とも呼ばれます）。文章をAIに読み込ませると、その文章の意味に応じた座標（数字の並び）が出力されます。意味が近い文章ほど、座標同士の距離が近くなる。これがVectorの正体です。

この仕組みがあると、キーワードが一致していなくても、意味が近い文章を見つけ出せます。「愛犬」と「ペットの世話」は、単語としては1文字も一致しません。それでも、Vectorの世界では近い場所に座標を持ちます。

**前回の「キーワードを覚えていないと二度と出てこない」という壁は、これで越えられます。**

## Graph（グラフ構造）——点と線で関係をたどる

友人関係を思い浮かべてください。

あなたには友人がいて、その友人にはまた別の友人がいます。あなたから見ると、直接の友人は「1手先」、友人の友人は「2手先」です。この「人」を点（**ノード**）、「友人関係」を線（**エッジ**）として表したものが、**Graph**（グラフ構造）です。

グラフの価値は、この**多段階のつながりを機械的にたどれる**ことにあります。「Aさんから2手先にいる人は誰か」という問いに、線をたどるだけで答えが出ます。路線図で「新宿から乗り換え1回で行ける駅」を調べる感覚に近いものです。

## RAG（検索してから答える仕組み）

AI（**大規模言語モデル**。ChatGPTのような、大量の文章を学習して自然な文章を生成できるAIのことです）には、知識の限界があります。学習した時点までの情報しか持っておらず、あなたの手元にある非公開の資料も知りません。

この限界を補うのが**RAG**（検索拡張生成）です。仕組みはシンプルです。**AIが答えを作る前に、関連しそうな資料を検索し、その内容を読んでから回答を生成します。**

試験におけるカンニングペーパーのようなものです。ただし、正々堂々と参照が許されているカンニングペーパーです。

RAGがあることで、AIは学習していない最新情報や、手元の資料に基づいて回答できるようになります。

## GraphRAG——VectorとGraphを、AIが自動で融合させる

ここまでの3つを組み合わせたものが、**GraphRAG**です。Microsoft Researchが2024年に発表した手法で、現在では企業向けRAGにおける主流の考え方になっています。

核心はここです。**GraphRAGでは、Graph（つながりの構造）自体を、人間ではなくAIが自動で作ります。**

処理の流れはこうなります。

```
大量の文章をAIに読ませる
→ 「これは誰の話か」「何と何が関係しているか」を自動抽出
→ 点と線として、つながりの地図を自動構築
→ 質問が来たら、意味の近さとつながりの両方から関連情報を集める
→ 集めた情報をもとに、AIが回答を生成する
```

Obsidianの`[[リンク]]`との違いが、ここで明確になります。Obsidianでは、人間が「これとこれは関係がある」と判断し、手作業でリンクを張ります。GraphRAGでは、**その判断自体をAIが行います。**

しかも、あなたが気づいていなかった関係——3年前に書いた文章と先週書いた文章のつながりのような——も、機械的に発見してくれます。

前回、手動リンクには「自分がすでに重要だと思っているものにしかリンクを張れない」という限界があると説明しました。GraphRAGは、この限界そのものを解消する設計になっています。

## どこにコストがかかるのか——AIとプログラムの分担

ここまでで仕組みは理解できたと思います。もう1つだけ、次回のために知っておくと役立つことがあります。

**この処理のうち、どこがAIの仕事で、どこが普通のプログラムの仕事なのか。** ここを知ると、「なぜGraphRAGは高いのか」が一発でわかります。

まずVector側の分担です。

```
①文章を分割する            → プログラム（機械的なルールで切るだけ）
②意味の座標に変換する       → AIモデル
③検索時に距離を計算する     → プログラム（数値の計算）
```

意外に思われるかもしれませんが、**②で単語ごとに重要度を判定しているわけではありません。** 文章全体を一気に読んで、意味を圧縮した1つの座標を出しています。だから精度が高い代わりに、なぜその2つが近いと判断されたのかは直接には見えません。

次にGraph側です。ここが本題になります。

```
①登場する人物・概念を抜き出す  → AI
②それらの関係を判定する        → AI
③関係に名前をつける            → AI
④つながりの地図に書き込む      → プログラム
```

**関係を見つける工程が、丸ごとAIの仕事になっています。** しかも文章のかたまりごとに、毎回AIを呼び出します。

全体を表にすると、こうなります。

| 工程 | 担当 | コスト |
|---|---|---|
| 文章の分割 | プログラム | ほぼゼロ |
| 意味の座標化 | AIモデル | 中 |
| 人物・概念の抽出 | **AI** | **高** |
| 関係の判定と命名 | **AI** | **高** |
| つながりの強さの計算 | プログラム | 低 |
| かたまりの検出 | プログラム | 低 |
| かたまりごとの要約 | **AI** | **高** |
| 書き込み | プログラム | ほぼゼロ |

**AIが関わる工程だけが、費用の主犯**だとわかります。

そして重要なのは、**この高コストな工程を「いつ実行するか」で総額が大きく変わる**ということです。全部を事前に一括で処理するのか、必要になってから処理するのか。ここが次回の話の核心になります。

## まとめ

- Vectorは、文章の意味を座標として数値化したもの。キーワードを覚えていなくても探せる
- Graphは、点と線で多段階のつながりを表す構造
- RAGは、AIが答える前に関連資料を検索する仕組み
- GraphRAGは、この3つをAIが自動で融合させる手法。手作業のリンク張りを根本から不要にする
- ただしAIが関わる工程は高コスト。「いつ実行するか」で総額が変わる

次回は、この技術を**個人がどこまで使うべきか**を扱います。全部やる必要はありません。蓄積量に応じた段階別の判断基準と、実際に動かせる実装用のプロンプトまで用意します💡
