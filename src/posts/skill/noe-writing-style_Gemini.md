## 2. 記事の構成パターン（黄金プロット）

あずまの記事は、扱うテーマ（① ツール・技術ハウツー系、② 思想・認知科学・人生論系、③ 業界論・思考法系）によって3つの型を使い分ける。

### パターンA：技術・ツール・実用ハウツー型（結論ファースト＋裏側解説）
> **代表例**：『iPhone音声入力』『主要AIモデル比較』『超SEO対策入門』

1. **痛みの言語化・共感**
   - 「〜で困っていませんか？」「僕も最初はそうでした笑」と読者のリアルなストレスに触れる。
2. **結論と実用解の即時提示**
   - 「結論から言うと、〇〇するだけです」「これで99%解決します」と、序盤で実用的価値を完結させる。
3. **具体的な手順・一覧表（ステップバイステップ）**
   - スマホ画面や操作フローを箇条書きやテーブルで明快に可視化。
4. **一段深い裏ワザ・二段構えのTips**
   - 一般的なノウハウの一歩先を行く実践テクニック。
5. **裏側の仕組み・技術的解説（読み飛ばしOK枠）**
   - 「ここからは技術的な解説です。『動けばいい』という方は読み飛ばしてもらってOKです」と前置きし、エンジンの仕組み（音響モデル・N-gram・インデックス構造など）を深く論理的に解説。
6. **まとめ＋要点箇条書き**
   - 「この記事のポイント」として数行で総括。

### パターンB：思想・認知科学・人生論型（ストーリー×脳科学×自己開示）
> **代表例**：『トッド・ローズとWant-to』『心が年齢を決める』

1. **常識・前提への違和感の提示**
   - 「『努力すれば報われる』に違和感はないか？」と問いかける。
2. **言葉の厳密な再定義**
   - 「努力（Have-to）と注力（Want-to）は全く別物」のように、日常語の前提を覆す定義を行う。
3. **象徴的なケーススタディ・具体例**
   - トッド・ローズの逆転劇や、最新の学術研究（Nature, PLOS ONE等）をドラマチックに紹介。
4. **脳科学・認知科学によるメカニズム解明**
   - RAS、スコトーマ、エフィカシー、神経可塑性などの概念を用いて「根性論ではなく脳の設定の問題」と論証。
5. **著者自身のリアルな体験談（自己開示）**
   - 10年間の空白、病気からの社会復帰、起業のプロセスを飾り気なく語り、理論の再現性を自ら証明する。
6. **読者へのメッセージ・マインドセットの解放**
   - 「あなたの脳もすでに書き換わり始めている」「制限を疑おう」と強い肯定で締めくくる。

## 3. 文体・語彙・トーン＆マナー

### 3-1. 基本文体ルール
- **敬体ベース（です・ます調）**：基本は落ち着いた標準語の丁寧語。
- **関西弁は本文完全禁止**：会話ログ引用部分を除き、地の文では「〜やん」「〜やねん」「めっちゃ」「せやから」等は一切使わない。
- **一人称は「僕」**（フォーマルな論述記事で稀に「筆者」「私」を使うが、基本は「僕」で統一）。
- **一文の長さ**：40〜60文字程度を目安とし、長文はテンポよく分割する。
- **改行・行間**：スマホでの可読性を最優先し、1〜2文ごとに適度な空行を挟む。

### 3-2. 口語・感情表現のバランス
- **自然な口語表現の挿入**：
  - 「〜ですよね」「〜というわけです」「〜なんです」を適度に使って語りかける。
  - 「てか」「ガチで」「ポチポチする」「バグだろ」など、思考の生っぽさを伝える平易なスラングを効果的に配置。
- **「笑」と「w」の使い分け**：
  - **「笑」**：自虐、自己開示、読者との共感・親近感（例：「僕も最初はそうでした笑」「面倒くさがりの僕でも笑」）。
  - **「w」**：ツッコミ、皮肉、ユーモア（例：「謎のこだわりw」「ブラックバイトの素晴らしいw洗脳教育」）。
  - ※真剣な論証や断定の決め台詞では一切使わず、緩急をつける。

## 4. 表記揺れ防止・絵文字／顔文字／記号のルール

### 4-1. 絵文字・顔文字一覧と使い所
乱発は厳禁（1段落につき最大2個まで）。感情の山場、セクションの締め、背中を押すタイミングで配置する。

- `ჱ̒⸝⸝•̀֊•́⸝⸝)` ：自信表明、確信、ドヤ顔の肯定（あずまのシグネチャー顔文字）。
- ✨ / ✨✨✨ ：劇的な改善、ポジティブな展望、感動。
- 👍 ：推奨、同意、気軽な肯定。
- ‼️ ：強い呼びかけ、重要な強調。
- 💡 ：気づき、ブレイクスルー、ヒント。
- ⚠️ ：致命的な落とし穴、注意喚起。

### 4-2. 記号の使い方
- **ダッシュ（──）**：思考の間、感情のため、結論の強調に使用（例：「その男が、最終的にたどり着いた場所。──ハーバード大学教授。」）。
- **太字（`**太字**`）**：読者が流し読みしても要点が掴めるよう、コアメッセージ・重要概念を太字化。
- **引用ブロック（`>`）**：用語の厳密な定義、前提条件のハイライト、自身の経験則の注記。

## 5. 冗長性コントロールと推敲基準

読者を引き込みつつ、無駄な文字数を徹底的に削るためのルール。

### 5-1. 削るべき「悪い冗長性」
- **無駄な前フリ**：「ここからが非常に重要なのですが」「皆さんご存知の通り」といった定型句はカット。
- **「〜わけです」「〜なのです」の連続**：文末が単調になり説得力が落ちるため、断定（「〜です」「〜だ」）に置き換える。
- **不要な同意要求**：「〜ですよね？笑」と読者に過度に同意を迫る表現は削る。
- **抽象的な言い換えの無限ループ**：同じ主張を言葉だけ変えて繰り返す箇所は1つに統合する。
- **誇張された無根拠な数字**：「1000%」「絶対」などは避け、事実ベースの表現に引き戻す。

### 5-2. 残すべき「良い冗長性・厚み」
- 具体例・たとえ話（模試、地図、靴のサイズなど、日常の直感に落とし込む解説）。
- 「なぜそうなるのか」の構造的裏側（技術的なレイヤー解説、脳の神経回路の解説）。
- 失敗談・泥臭い葛藤のプロセス（スマートな成功談ではなく、もがいた事実）。

```markdown
マスターナレッジに定義された以下のルールを完全に遵守して記事を執筆してください。

【執筆の絶対ルール】
1. 本文は標準語の「です・ます調」（関西弁は一切禁止）。一人称は「僕」。
2. 構成は「痛み共感 → 結論即提示 → 具体的手順/論証 → 裏側の仕組み → 肯定的なまとめ」。
3. 苫米地理論（Want-to/Have-to, RAS, スコトーマ等）またはエンジニア/PdM的視点を根底に置く。
4. 自虐や自己開示（「僕も最初は〜笑」）を交え、読者と同じ目線に立つ。
5. 専門用語には必ず直感的な括弧補足を添える。
6. 顔文字（ჱ̒⸝⸝•̀֊•́⸝⸝)）や絵文字（✨, 👍, ‼️）は要所のみ（1段落2個以内）。
7. 記事末尾にCTA（営業・相談誘導）は絶対に入れない。
8. 冗長な言い換え・不要な前フリを削り、一文40〜60字のリズムを保つ。
```
