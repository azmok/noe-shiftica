先に、いちばん都合の悪いことから書きます。

「Obsidian×AIでAI社員を作る」——これは、**作れます。** 嘘ではありません。

ただし、その仕組みの中で**Obsidianは何もしていません。**

実際に働いているのは、まったく別のソフトウェアです。そしてそれは無料で、誰でも今日から使えます。Obsidianを買う必要も、Obsidianの使い方を学ぶ必要も、Obsidian前提の講座を受ける必要もありません。

この記事では、なぜそう言えるのかを専門知識ゼロから解説します。読み終える頃には、「AI社員」と呼ばれているものが技術的に何なのか、自分で判断できるようになっているはずです。

## まず、Obsidian社自身の立場から

技術の話に入る前に、前提として置いておきたい事実があります。

ObsidianのCEOであるSteph Ango氏は、Obsidianを「考えるための道具であって、ユーザーの代わりに考えようとする道具ではない」と繰り返し位置づけています。より多くの判断を自動化に委ねれば仕事が良くなる、という発想そのものを拒否しているんです。

同社の設計思想では、自動化がワークフローに登場すること自体は否定されません。ただしそれは、ユーザーが選び、設定し、範囲を限定するもの。製品の中心的な知能として押し付けられるものではない、とされています。

つまり——**Obsidianは今も、そしてこの先も、自動化の基盤を目指していない。** 「今できない」ではなく「そこは伸ばさない方針」という意味です。

では、実際に自動化を担っているのは何なのか。ここから技術の話に入ります。

## そもそも「AIエージェント」とは何か

まず言葉の整理からです。

普段使うAIチャットは、こちらが1つ質問して、AIが1つ答える形です。これを一歩進めたものが**AIエージェント**です。

```
AIチャット   ：「このバグの原因を教えて」→ 答えが返ってくる
AIエージェント：「バグを直して」→ 自分でファイルを読み、原因を探し、
              修正し、動作確認まで済ませる
```

違いは、**目的だけ渡せば、途中の手順を自分で決めて実行する**という点です。人間が1手ずつ指示しなくても動きます。

そして「AI社員」と呼ばれているものの正体は、このAIエージェントに次の2つを足しただけです。

```
AIエージェント
＋ ナレッジ（参照させる情報）
＋ 役割定義（どう振る舞うかの指示書）
```

海外の開発者コミュニティでは、これを「Role-based multi-agent（役割ベースの複数エージェント）」と呼びます。「社員」という言葉は使いません。新技術の名前ではなく、既存の仕組みに親しみやすい呼び名がついているだけ、ということです。

## コンテキストウィンドウ——AIの「作業机」

ここが、この記事でいちばん重要な概念です。

AIには**コンテキストウィンドウ**という制限があります。ざっくり言えば、**AIが一度に見渡せる情報の量**です。作業机の広さをイメージしてください。

会話を続けると、それまでのやり取りが全部この机の上に積み上がっていきます。そして机には広さの限界があるので、いずれ溢れます。

問題はそれだけではありません。**机が散らかると、AIの精度そのものが落ちます。**

この現象には名前がついていて、**Lost in the Middle**（中抜け）と呼ばれます。AIは机の上の情報のうち、最初と最後には強く反応するのに、**真ん中に埋もれた情報を見落としやすい**という性質を持っています。長い会議の冒頭と結論だけ覚えていて、中盤を忘れてしまう感覚に近いものです。

そしてこれは、机を広くすれば解決する話ではありません。

```
机が広い（コンテキストが大きい）
　　≠
机の上のもの全部を、均等に見ている
```

**情報が「収まる」ことと、「ちゃんと読まれる」ことは別問題**なんです。ここが、次の話の土台になります。

## 「役割を持たせる」とは、技術的に何をしているのか

では「コーダー役」「チェック役」のように役割を分けるとき、技術的には何が起きているのか。

多くの人がイメージするのは、こういうものだと思います。

```
1人のAIに
「今はコーダーとして振る舞って」
「次はチェック役として振る舞って」
と指示を切り替える
```

これは**役割分担ではありません。** 同じ1つの机の上で、AIが服を着替えているだけです。コーダーとして書いた内容も、チェック役として検証した内容も、全部同じ机に積み上がっていきます。机はどんどん散らかり、中抜けが起きやすくなります。

本物の役割分担は、こうです。

```
コーダー役  ：専用の机で作業する（他の作業は机の上にない）
チェック役  ：別の専用の机で作業する
統括役     ：それぞれから結果の要約だけを受け取る
```

**机そのものを物理的に分ける。** これが技術的な役割分担の本体です。専門用語では「コンテキストの分離」と言います。

こうすると何が良いのか。

- 各AIの机が散らからないので、精度が落ちない
- 独立した作業なら、複数の机で**同時に**進められる
- 統括役の机には要約だけが届くので、全体を見渡す余裕が残る

つまり**「役割を与える」の本質は、キャラ設定ではなく机の分離**です。ここを理解すると、次の話が一気にクリアになります。

## エディタと実行環境——Obsidianはどちらか

ソフトウェアには、大きく分けて2つの種類があります。

| 種類 | 役割 | 例 |
|---|---|---|
| **エディタ／保管庫** | 文章を書く。ファイルを置く | Obsidian、メモ帳、VS Code |
| **エージェント実行環境** | AIを起動する。机を割り当てる | Claude Code など |

Obsidianは前者です。文章を書いて、`.md`ファイルとして保存する。これは非常に優秀にこなします。

ですが、**AIを起動する機能も、机を分ける機能も、複数のAIに仕事を振り分ける機能も、Obsidianには存在しません。**

これは欠陥ではありません。そもそもそういう製品ではない、という話です。冒頭で引用したCEOの発言は、まさにこれを言っています。

## 実態の分解——何が100%仕事をしているのか

ここまでを踏まえて、「Obsidian×AIでAI社員」という構成を分解してみます。

```
├─ Obsidian      ：テキストエディタとして機能
│                  → メモ帳でもVS Codeでも代替できる
├─ .mdファイル    ：ただの設定ファイル
│                  → 中身は役割の指示書。書式が決まっているだけ
└─ Claude Code   ：★ 100%ここが仕事をしている
                   → AIの起動、机の分離、役割の割り振り、並列実行
                   → すべて標準機能。追加費用ゼロ
```

役割分担の本体は、**常にObsidianの外側にあります。**

さらに言えば、**Obsidianの固有機能はこの仕組みに1ミリも寄与していません。** 相互リンクも、グラフ表示も、プラグインも、エージェントの動作にはまったく関与しません。ファイルが`.md`形式であることすら、Claude Code側の都合であってObsidianの都合ではありません。

言い換えると——**Obsidianは、あってもなくても同じ**なんです。フォルダに`.md`ファイルが入っていれば、それで足ります。

## まとめ

- Obsidian×AIで「AI社員」は作れる。ただしObsidianは何もしていない
- AIエージェントとは、目的を渡せば手順を自分で決めて実行する仕組み
- コンテキストウィンドウはAIの作業机。散らかると精度が落ちる（Lost in the Middle）
- 役割分担の本体は、キャラ設定ではなく**机の分離**
- その機能を提供しているのはClaude Code。Obsidianはテキストエディタとして使われているだけ

つまり、**学ぶべきは「Obsidianの使い方」ではなく「机の分け方」**だった、ということです。
