SNSでこういう投稿を見かけました。

> **Obsidian × AI で、既存の知識を資産化する**

会社に溜まった資料、過去に書いた文章、調べてまとめたメモ——そういったものをObsidianに集めて、AIと組み合わせて活用しよう、という趣旨です。

気になったので、実際に使ってみました。正直な第一印象はこうでした。

**「これが第二の脳？ただの.mdメモアプリとあんまり変わらない…」**

ただ、感覚だけでは議論になりません。そこで、こういう手順で検証することにしました。

```
① 「Obsidianが何か」を正確に定義
        ↓
② 「データ活用の用途」を整理
        ↓
③ 「Obsidian×用途毎」が最適か判定
```


<a id="s1"></a>

## 第1部：Obsidianとは何か

使ったことのない方のために、ここから説明します。

Obsidianは**メモアプリの一種**です。そして、その特徴は**4つだけ**です。

| No. | 特徴 | 内容 |
|:---:|:---|:---|
| 1 | .md特化 | メモが1件1ファイルとして手元に保存される |
| 2 | **[[記事名]]** | **メモ同士のつながりを、手で登録できる** |
| 3 | グラフビュー | 登録したつながりを、点と線の図で表示できる |
| 4 | プラグイン | 機能を追加できる（AI関連を含む） |

**この4つが、Obsidianの本体です。** それ以上でも以下でもありません。

### ①「.md特化」とは

**Markdown**（マークダウン）というのは、記号で書式を表す書き方のことです。

```
# これは見出し

- これは箇条書き

**これは太字**
```

### ② ③ つながりの登録と、その可視化

ここが目玉機能であり、「第二の脳」と呼ばれる理由です。次の章で詳しく見ます。

### ④ プラグイン

後から機能を追加できる仕組みです。AI関連のものもあります。

⚠️ **ただし1つ注意があります。** プラグインで追加した機能は、**Obsidianの本体機能とは別に動きます。** この点が後半で効いてくるので、覚えておいてください。

<a id="s2"></a>

## [[リンク]]とは、結局何なのか

### まず、実際に書くとどうなるか

メモを書いているとき、他のメモを参照したくなったとします。そのときは、こう書きます。

```
今日は開発環境について調べた。
詳しくは [[Docker入門]] を見ること。
```

**角カッコを2つ重ねて、中にメモの名前を書く。** それだけです。

するとその部分がクリックできるようになり、押すと「Docker入門」というメモに飛べます。**Wikipediaの記事内のリンクと同じ感覚**です。

そして**グラフビュー**を開くと、メモを点、リンクを線として、全体が1枚の図で表示されます。**頭の中の連想が、そのまま図になったように見えます。**

実際、初めて見たときはかなり感動します。

### では、そこで作られたものは何か

ここからが本題です。

`[[Docker入門]]` と書いたとき、実際に作られた情報は**たった1つ**です。

> **「このメモと、Docker入門というメモは、関係がある」**

それだけです。**関係の内容でも、意味でもありません。** 「AとBはつながっている」という、それだけの記録です。

メモが100件あって、リンクを300本張ったとします。すると**あなたは300件の「つながりの記録」を、手作業で1件ずつ作った**ことになります。

### データベースの言葉で言うと

この「つながりだけを記録した一覧」には、正式な呼び名があります。**交差テーブル**といいます。

クラスの名簿でたとえます。

```
【名簿】
  1番 田中さん
  2番 佐藤さん
  3番 鈴木さん

【友達の組み合わせ表】  ← これが交差テーブル
  1番 と 2番 は友達
  1番 と 3番 は友達
```

**名簿とは別に、「誰と誰が友達か」だけを記録した表を作る。** これが交差テーブルです。

Obsidianでは、**メモ1件が名簿の行、`[[リンク]]`が組み合わせ表の行**にあたります。

### そして、これは本来

**データベースの世界では、この組み合わせ表は自動で作られるのが普通です。** 人間が1件ずつ手で書くものではありません。

つまりObsidianの`[[リンク]]`は——

> **本来なら自動で作られるはずの「つながりの記録」を、人間が手作業で入力している**

ということになります。**これが、Obsidianの中核機能の正体です。**



<a id="s3"></a>

## 第2部：データ活用の用途は４つに分類される

ここからが検証です。

「既存のデータを資産化する」と言ったとき、**実際にやりたいことは何でしょうか。**

整理すると、**4つの動詞**に分かれます。

| 動詞 | やりたいこと | 具体例 |
|:---:|:---|:---|
| 取り出す | 必要な情報を引く | 「あの件、どうなってたっけ」 |
| 束ねる | 全体を要約・分析する | 「全体として何が言えるか」「傾向は」 |
| **見つける** | **気づいていない関係を発見する** | **「この2つ、繋がってたのか」** |
| 作る | 材料にして新しく生み出す | 下書き、壁打ち、戦略の検討 |

<a id="s4"></a>

## 照合してみる

<a id="s4a"></a>

### 照合①【取り出す】——△

Obsidianの検索は、**キーワード検索**です。入力した文字と一致する文字を探す方式です。

**書いた言葉を覚えていれば、これで足ります。** 十分に速く、確実です。

ただし条件があります。

> **「そのメモに何と書いたか」を覚えていること。**

3年前に書いたメモを、あなたはどんな言葉で書いたでしょうか。「愛犬の世話」か、「ペットのケア」か。**覚えていなければ、そのメモは存在しないのと同じです。**

そして**量が増えるほど、時間が経つほど、この「覚えていない領域」が増えていきます。**

**判定：△**——できるが、記憶に依存する。量・経過時間が増えると弱くなる。

<a id="s4b"></a>

### 照合②【束ねる】——×

「この3年分のメモから、自分の関心がどう変化したかをまとめて」

**Obsidianには、この機能がありません。**

できるのは検索と表示までで、**複数のメモを横断して要約したり、傾向を出したりする仕組みは持っていません。**

「プラグインを入れれば」と思われるかもしれません。ですが、それは**Obsidianの機能ではなく、追加したプラグインの機能**です。

**判定：×**——本体機能としては存在しない。

<a id="s4c"></a>

### 照合③【見つける】——×

**ここが最も重要な照合です。**

グラフビューを見ると、点と線がつながっていて、いかにも「発見」が起きそうに見えます。

ですが、思い出してください。**その線は、あなたが手で張ったものです。**

```
グラフビューに表示されるもの
  = あなたが「関係がある」と判断して登録したもの
  = あなたがすでに知っている関係
```

**知らなかった関係は、1本も表示されません。** 登録していないのですから、当然です。

#### そして、人は「知っているもの」しか登録できない

ここに、もう1段深い問題があります。

人間の脳には**「注意のフィルター」**があります。**今の自分が重要だと感じているものだけを意識に上げる**仕組みです。興味のないものは、目の前にあっても気づけません。

つまり——**あなたがリンクを張れるのは、すでに重要だと思っている範囲の中だけ**です。

3年分のリンクは、**3年分の思い込みの記録**でもあります。当時つながりに気づかなかった2つのメモは、今も切り離されたまま。そして**気づいていないのだから、探すこともできません。**

> 第一の脳がすでに信じていることしか映せないものは、第二の脳ではありません。
> **ただの鏡です。**

#### 実例：最も成功している実践者は、手で張っていない

この判定を、実例で裏付けます。

AI研究者のAndrej Karpathy氏が、2026年に自身の知識ベースの設計を公開しました。**約100記事・40万語**の規模です。

構成は3つのフォルダだけ。**資料を放り込むと、AIがそれを読んで整理し、ページ同士のリンクも自動で張ります。**

そして彼は、その結果をObsidianで見ています。**ただし——**

> **リンクを張っているのは人間ではなく、AIです。**
> Karpathy氏自身も、**Obsidianは推奨だが必須ではない**としています。

💡 **つまり「見つける」を成立させているのは、Obsidianの外側にある仕組み**です。Obsidianは、AIが張った線を眺めるための窓として使われているだけです。

**判定：×**——手で張ったものしか出てこない。それは「すでに知っていること」でしかない。

<a id="s4d"></a>

### 照合④【作る】——○

最後は、素直に評価できる項目です。

下書きを書く、考えを整理する、AIに読ませる材料を置いておく。**この用途では、Obsidianは優秀です。**

理由は3つあります。

1. **書き心地**——書きながら見た目が確認でき、スマホでも打ちやすい。地味ですが、自作すると最も骨が折れる部分です
2. **他のツールと組み合わせやすい**——中身はただのフォルダとファイルなので、他のアプリやAIツールがそのまま扱えます
3. **同期の安定性**——パソコンとスマホで内容を揃える仕組みが堅実で、バッテリーにも優しい

**判定：○**——書く道具、置く道具としては優秀。

### 照合結果

| 動詞 | 判定 | 理由 |
|:---:|:---:|:---|
| 取り出す | △ | キーワードのみ。記憶に依存する |
| 束ねる | × | 本体機能として存在しない |
| **見つける** | **×** | **手で張ったものしか出てこない** |
| 作る | ○ | 書く道具としては優秀 |

**4つのうち、応えられるのは1.5個。** そして**「第二の脳」の核心である【見つける】が×**です。

## 【本題】既存文書の資産化に向かない4つの理由

ここまでは、Obsidianを一般的に評価しました。

ここからは、冒頭のSNSの主張に絞ります。**すでにある文書**をObsidianに入れて活用する場合です。

**結論から言うと、これは最悪の選択肢です。** 理由を4つ挙げます。

1. .md形式に直すコスト(AIの演算)
2. 直した所で、[[リンク]]が存在しない
3. グラフビューも存在しない


わざわざ「Obsidian」に移行する意味が最初からありません。

既存データがすでにある場合、おそらく

1. 大量のテキストファイル
2. データベース

どちらかでしょう。そうであるなら、わざわざObsidianという「マークダウンアプリ」に依存する今が最初からありません。

既存データを４つの方法で活用するなら、
### 1.の場合
  - RDB形式に変換 → vectorDB, GraphDB, その他ハイブリッドなデータ活用
	- .md形式に変換 → [🔴必要ある？ RDBでよくない？検証必要]

### 2.の場合
- RDBをそのまま活用

の方が、AIの計算コストも減り、データ活用の観点から至極最適な選択です。それは過去のデータ活用の科学的研究・開発者の現状と実例を鑑みれば明らかです。
